# ADR-0007: Transfer buffers and "approximate" labels for bus times

- Status: Accepted
- Date: 2026-10-23

## Context

Delhi's Open Transit Data portal states that bus arrival and departure times in
`stop_times.txt` are rough estimates, generated by assuming a constant travel speed. Real
buses will run early or late, and as far as we know no public real-time feed is available.
A planner that trusts these times can suggest connections that are impossible in practice,
such as a 1-minute change onto a bus.

## Decision

- Keep scheduled times, but add a **minimum transfer buffer** when boarding a bus whose
  times are estimated. The buffer size is configurable and set during the data work.
- Mark legs with estimated times, and show them as **approximate** in the UI ("~08:14").
- Feed this into the **reliability score** used to rank and label options (ADR-0003).

## Alternatives considered

- **Model buses as frequency-based** ("every N minutes"). More honest about uncertainty,
  but departs from the GTFS trip model RAPTOR uses.
- **Trust the data.** Simplest, but plans look precise and fail in practice.

## Consequences

- Each feed or route needs a "times are estimated" flag, set during import.
- Buffers make some journeys slower on paper, which is the intended trade-off.
- The reliability score needs a defined, explainable formula, designed in M4.
